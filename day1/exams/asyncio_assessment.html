1

The Event Loop & Context Switching

Why is the Python asyncio Event Loop generally faster for I/O-bound operations compared to OS-level multithreading?

Explanation:

Correct Answer: B. Context switching at the OS level (threads) is expensive because it requires the kernel to save/load CPU registers and memory maps. Asyncio runs on a single thread and uses software-level (user-space) context switching instantly when await is called.

2

Async Primitives: Coroutines

What happens if you define async def fetch_data(): ... and simply call data = fetch_data() without using await or creating a Task?

Explanation:

Correct Answer: C. Coroutines in Python are passive. Merely calling an async def function only instantiates the coroutine object. It must be awaited or scheduled on the Event Loop to actually run.

3

Async Primitives: Tasks

What is the primary practical purpose of an asyncio.Task?

Explanation:

Correct Answer: A. Wrapping a coroutine in a Task using asyncio.create_task() registers it with the Event Loop, allowing it to run concurrently in the background while your main code continues executing.

4

Blocking the Event Loop

If you accidentally place a synchronous, CPU-bound operation (like a heavy `for` loop) or time.sleep(5) inside an async endpoint, what is the consequence?

Explanation:

Correct Answer: C. Because the Event Loop runs on a single thread, any synchronous blocking code halts the entire process. This is why you must use asyncio.sleep() for I/O waits, or asyncio.to_thread() for heavy CPU tasks.

5

Production Pitfalls: Silent Failures

Analyze this code snippet. Why does this completely fail to catch the exception raised by the background worker?

try: asyncio.create_task(background_worker_that_crashes()) except Exception: print("Caught error!")

Explanation:

Correct Answer: A. The execution immediately steps out of the `try` block. When the background task crashes later, the exception is stored inside the Task object as an unhandled exception, causing a "Silent Failure".

6

Modern Structured Concurrency

In Python 3.11+, what is the recommended, modern approach to spawn multiple background tasks, ensure they all complete, and guarantee that if one fails, the others are properly cancelled and the errors are grouped?

Explanation:

Correct Answer: B. TaskGroup introduces Structured Concurrency. It serves as an asynchronous context manager that waits for all child tasks to finish, and if any raise an exception, it safely cancels the siblings and groups the errors into an ExceptionGroup.
