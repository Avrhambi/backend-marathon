1

Pydantic vs. DataClasses

What is the primary difference between standard Python @dataclass and Pydantic's BaseModel when handling raw input data?

Explanation:

Correct Answer: C. The core philosophy of Pydantic is "parsing, not just validating". While a standard dataclass will happily accept a string when an integer was specified, Pydantic will actively try to convert (coerce) it at runtime, and throw a ValidationError if it fails.

2

Type Coercion

If you define a Pydantic field as age: int and instantiate the model with age="25" (a string), what does Pydantic do by default?

Explanation:

Correct Answer: A. Pydantic is designed to parse untyped data (like HTTP request payloads or environment variables) into typed Python objects. Since `"25"` can safely be cast to an integer, Pydantic performs this coercion automatically.

3

Declarative Field Constraints

How do you cleanly enforce that an integer field (e.g., price) is always strictly greater than zero using Pydantic V2?

Explanation:

Correct Answer: B. The Field function in Pydantic is used to apply metadata and declarative constraints to fields. gt stands for "greater than", ge for "greater than or equal to", etc.

4

Custom Validators

When writing a custom @field_validator in Pydantic V2, what should the method do to signal that validation has failed?

@field_validator("email") @classmethod def check_domain(cls, value: str): if "@" not in value: # What goes here?

Explanation:

Correct Answer: B. Validators should raise a standard Python exception like ValueError or AssertionError. Pydantic catches these internally and aggregates them into a structured ValidationError indicating which fields failed and why.

5

Serialization

What is the recommended method in Pydantic V2 to convert a populated BaseModel instance back into a standard Python dictionary?

Explanation:

Correct Answer: C. In Pydantic V2, model.model_dump() is the standard way to serialize models to a dictionary (replacing the deprecated `.dict()` from V1). To get a JSON string directly, you use model.model_dump_json().

6

Direct JSON Parsing

Pydantic V2 uses a high-performance Rust backend. What is the most efficient way to parse a raw JSON string directly into a model instance without calling json.loads() first?

Explanation:

Correct Answer: B. model_validate_json() relies directly on Pydantic's Rust-based core engine, making it drastically faster than parsing the JSON in Python first and passing the resulting dict to the model. (Note: parse_raw is deprecated in V2).

7

Cross-Field Validation

If you need to validate that password and password_confirm match, which decorator is designed for validating multiple fields against each other?

Explanation:

Correct Answer: B. A @model_validator(mode='after') runs after all individual fields have been validated. It receives the entire model instance (or dictionary, depending on the mode), allowing you to safely compare multiple fields like passwords.

8

Handling Field Aliases

Your frontend sends JSON with camelCase keys (e.g., firstName), but your Python backend uses snake_case (first_name). What is the cleanest way to handle this mapping in Pydantic?

Explanation:

Correct Answer: B. Aliasing is built deeply into Pydantic. You can specify a manual alias in the Field definition, or use a global alias_generator (like pydantic.alias_generators.to_camel) inside model_config = ConfigDict(...) to handle the entire model automatically.

9

Forbidding Extra Attributes

By default, if a client includes extra JSON fields that are not defined in your Pydantic model, Pydantic simply ignores them. How do you configure the model to raise a ValidationError instead?

Explanation:

Correct Answer: A. The ConfigDict is the standard way to alter model behavior in V2. Setting extra='forbid' prevents clients from passing undocumented/junk payload data. (The default behavior is extra='ignore').

10

Under the Hood: Performance

Pydantic V2 is highly celebrated for being significantly faster than Pydantic V1 (often 5x to 50x faster). What is the architectural reason for this massive performance leap?

Explanation:

Correct Answer: B. Pydantic V2 separated its validation engine into a separate package called pydantic-core, written in Rust. This allows it to perform schema generation, parsing, and strict validation at near native-C speeds while maintaining a Pythonic API surface.
